The 30-second version

  • Role: I acted as the analyst on an incident: given packet captures of intercepted traffic, reconstruct what an attacker positioned between two parties saw, changed and took.
  • Tools: Wireshark for visual, packet-by-packet inspection; pyShark (a Python wrapper around tshark) to automate the analysis; the protocol RFCs as the definition of "normal"; and password-cracking tools to judge how exposed captured credentials were.
  • Deliverables: a structured findings file answering the investigation questions, and a small program that repeats the core analysis automatically.
The case

What a man in the middle can do

In a man-in-the-middle (MITM) attack, someone inserts themselves into a conversation while both parties believe they are talking directly. On a local network the most common technique is ARP spoofing. Devices find each other by asking "who has this IP address?", and they trust whatever answer arrives. An attacker who keeps answering "the router is me" receives everyone's traffic first and quietly forwards it on.

Background

Where the attack shows up, layer by layer

A useful habit from this project was asking, for every clue, which layer of the network stack it lives in. The attacker's footprint looks different at each one.

7 · ApplicationHTTP requests, IRC chat, credentials and file transfers: what was said and taken.
4 · TransportTCP streams and ports: which conversations exist and how to reassemble them.
3 · NetworkIP addresses: who talks to whom, and unexpected hops in the path.
2 · Data linkMAC addresses and ARP: how the attacker got in the middle.
The investigation

How I worked the case

Survey before diving in

Use protocol hierarchy and conversation statistics to see which hosts, protocols and time windows matter. Thousands of packets shrink to a handful of interesting streams.

Find the insertion point

Look at the data-link layer for ARP anomalies: repeated unsolicited replies, and one MAC address claiming several IPs.

Read the application traffic against its RFC

HTTP (RFC 2616) and IRC (RFC 1459) define exactly what valid messages look like. Comparing captured traffic against the standard exposes injected or altered content.

Reassemble the conversations

Follow TCP streams to read whole exchanges, reconstruct transferred files, and identify which credentials crossed the wire.

Assess the damage

Captured password hashes are only as safe as the passwords behind them; testing them with a cracking tool shows how quickly weak ones fall.

Automate it

Rewrite the key filters with pyShark so the same analysis runs on the next capture without hours of clicking.

Automation

From clicks to code

Wireshark is ideal for understanding a capture; it is a poor way to answer the same question twice. The second deliverable was a program that applies display filters and extracts fields programmatically. This is the same "explore interactively, then automate" pattern I use for any data problem, and in real incident response it is what lets one analyst handle captures from many machines.

# the shape of it: open a capture with a filter, pull the fields you need
capture = pyshark.FileCapture(path, display_filter="arp")
for pkt in capture:
    record(pkt.arp.src_proto_ipv4, pkt.arp.src_hw_mac)
Defence

How to defend against it

Encrypt everything
TLS means an interceptor only sees ciphertext; HSTS prevents downgrades to plain HTTP.
Harden the LAN
Dynamic ARP inspection, DHCP snooping, port security and network segmentation.
Retire plaintext protocols
Use encrypted alternatives (e.g. IRC over TLS, SSH instead of Telnet).
Strong, unique passwords + MFA
Captured hashes of long passwords resist offline cracking; MFA makes stolen passwords insufficient.
Monitor
Alert on ARP anomalies and new devices claiming the gateway's address.
Looking back

What it taught me

  1. Plaintext is public. Watching a real login cross the capture made "use HTTPS" visceral.
  2. Specs beat intuition. When unsure whether something was suspicious, the RFC settled it.
  3. Explore, then automate. Interactive tools build understanding; scripts make it repeatable.
  4. Think in layers. Asking "which layer is this?" turned a wall of packets into a story.
Reference

Key terms

PCAP
A packet capture: a recording of network traffic.
ARP
Address Resolution Protocol: maps IP addresses to hardware (MAC) addresses on a LAN.
ARP spoofing
Sending forged ARP replies to redirect traffic through the attacker.
RFC
The published standard defining a protocol.
TCP stream
A full two-way conversation reassembled from individual packets.
pyShark / tshark
Python wrapper / command-line engine behind Wireshark.
HSTS
A header telling browsers to always use HTTPS for a site.
